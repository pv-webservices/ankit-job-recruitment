# Google Search Console — setup, indexing plan and monitoring

Site: **https://ankitjobs.in/** (canonical host is the apex domain, no `www`).
Sitemap: **https://ankitjobs.in/sitemap.xml** (generated by `src/pages/sitemap.xml.ts`; there is no sitemap index).

> Before the changes in this repository are deployed, the live site is built **without** a
> production origin: every page sends `noindex`, `robots.txt` is `Disallow: /` and the sitemap
> is empty. Deploy first, run the checklist below, then submit to Search Console.

## 1. Pre-launch / post-deploy checklist

## 2. Create the Search Console property (Domain property)

The domain's DNS is hosted at **Hostinger** (nameservers `pixel.dns-parking.com` / `byte.dns-parking.com`,
checked 16 Nov 2026). Add the TXT record there — not at GoDaddy or Vercel.

1. Open https://search.google.com/search-console and sign in with the Google account that
   should own the property (ideally the client's business account).
2. **Add property → Domain** → enter `ankitjobs.in` (no `https://`, no `www`) → Continue.
3. Copy the TXT value Google shows (`google-site-verification=…`).
4. In **Hostinger hPanel → Domains → ankitjobs.in → DNS / Nameservers → DNS records**:
   - Type: `TXT`, Name/Host: `@`, Value: the full `google-site-verification=…` string, TTL: default.
   - Save. Do not delete or edit the existing `A`/`CNAME` records that point to Vercel.
5. Wait a few minutes (DNS can take up to 24–48 h), then click **Verify** in Search Console.
   You can check propagation with `nslookup -type=TXT ankitjobs.in 8.8.8.8`.
6. Keep the TXT record permanently — removing it un-verifies the property.

A Domain property covers `https://`, `http://`, `www` and the apex in one place.

## 3. Submit the sitemap

1. Search Console → **Sitemaps** → enter `sitemap.xml` → **Submit**.
2. Opening the sitemap in a browser and seeing *"This XML file does not appear to have any style
   information"* is normal.
3. Status should become **Success** with 13 discovered URLs. If it shows **Couldn't fetch** or stays
   **Pending** for more than a few days: open the URL in a private window, confirm HTTP 200 and
   `Content-Type: application/xml`, confirm robots.txt is not `Disallow: /` (the pre-fix build), then
   resubmit. Don't assume "Pending" means everything is fine.

Use **URL Inspection → Request indexing** for 3–4 URLs per day as above; the sitemap covers the rest.
Requesting more often does not speed things up.

**Intentionally excluded (noindex, not in sitemap):**

- `/404/` and every unknown URL — error page, returns HTTP 404.
- `/candidate-registration/`, `/career/` — legacy URLs, 308-redirect to `/candidate-zone/` and `/current-openings/`.

**Possible blockers to watch:** the live site still serving the pre-fix build (noindex + `Disallow: /`);
`www` serving 200 instead of redirecting if `vercel.json` is not deployed; very similar pages being
grouped as "Duplicate without user-selected canonical" (each page has its own canonical, so this should not happen).

## 5. Monitoring plan (weeks 1–4)

| When | What to check |
|---|---|
| Week 1 | Sitemaps report = Success. **Pages** (Indexing) report: watch "Crawled – currently not indexed" and "Excluded by noindex" (should be empty apart from the 404 page). URL Inspection on `/` shows "URL is on Google" or a clear reason. Run PageSpeed Insights on `/` and `/current-openings/`. |
| Week 2 | **Pages** report: no "Server error (5xx)", "Not found (404)" for real pages, or "Redirect error". **Enhancements**: Breadcrumbs report should appear (BreadcrumbList is on 12 inner pages). Fix anything flagged and click **Validate fix**. |
| Week 3 | **Core Web Vitals** report (needs enough Chrome traffic — may stay empty for a small site; use PageSpeed Insights lab data meanwhile). **Performance**: first impressions/queries. Set up **Google Business Profile** with the same name, phone (+91 8348623389) and website URL. |
| Week 4 | Add the site to **Bing Webmaster Tools** (import from Search Console is the quickest) and submit the same sitemap. Re-check indexing; request indexing only for pages still "Discovered – not indexed". Update `current-openings` content whenever vacancies change so Google has a reason to recrawl. |

Google decides if and when pages are indexed; no timeline or ranking can be guaranteed.

## 6. Favicon in Google results

Favicons (`/favicon.ico` 16/32/48, `/favicon-48x48.png`, `/favicon-96x96.png`, `/apple-touch-icon.png`,
192/512 manifest icons) are generated from the approved logo with `npm run images:favicons`.
Google picks up a new favicon only after it recrawls the homepage — this can take days to weeks.
Requesting indexing of `/` may help but does not guarantee an immediate update.
There is no vector (SVG) logo in the project, so no `favicon.svg` is provided.
